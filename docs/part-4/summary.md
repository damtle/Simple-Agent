# 第四部分总结

第四部分把一个能运行的 Agent 收束为可观察、可测试、可复用的教学系统。

| 层次 | 建立的结构 | 回答的问题 |
|---|---|---|
| 恢复与停止 | Retry Policy、重复行动检测、确认和 `TerminationReason` | 失败后能否继续，什么时候必须停止 |
| 运行事实 | `AgentState`、Attempt、StepRecord、Execution Trace | 系统怎样到达当前结果 |
| 行为验证 | Mock LLM、Fixture、自动化测试和基础 Metrics | 修改后怎样证明原有行为仍然成立 |
| 公共实现 | `simple_agent` 包、模块边界和 Public API | 哪些职责已经稳定并值得复用 |
| 完整应用 | `examples/travel_assistant`、业务工具和 Evidence Reflection | 公共包怎样进入具体场景 |

可靠性不是“遇到异常就重试”，而是来自多个边界共同成立：

```text
非法输入被拒绝
+ 可恢复错误受到次数限制
+ 高风险行动需要程序确认
+ 每次结束都有明确原因
+ 状态与轨迹保存真实过程
+ 测试能够重复验证关键行为
```

最终形成的 `simple_agent` 包不是学习起点，而是前十四章职责逐渐稳定后的结果。教学快照继续留在 `code/chapter01`—`code/chapter14`，让读者看见结构怎样出现；公共实现只保留在根目录 `simple_agent/`，避免后续应用依赖多份代码。

第十六章的旅行助手完成了最后一次组合：应用层提供模拟数据、工具、Prompt 和答案检查，公共包负责 Agent Loop、Parser、重试、状态与轨迹。这个边界也说明，继续扩展真实天气、RAG、多智能体或浏览器控制时，不应把所有功能继续堆进 `Agent` 类，而应为新问题建立新的程序边界。

全书最终回答了最初的问题：

> 让模型提出结构化行动，让程序校验并执行行动，让环境反馈进入下一轮决策，再用有限控制、状态、轨迹和测试保证整个过程可理解、可停止、可验证。
