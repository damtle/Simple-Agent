# 第一部分：从程序到可对话模型

很多人会把“调用了大语言模型”直接等同于“具备 Agent”。这在学习初期很常见，但会导致方向偏差：

一个程序是否像 Agent，取决于它能否围绕目标持续观察环境，并根据反馈不断决定下一步。  
普通程序负责一次性处理输入，工作流负责按预设步骤推进，  
大语言模型负责理解与生成语言，  
而 Agent 在它们之上，还要形成可持续闭环。

这一部分不会一上来就构建完整 Agent，而是像搭楼梯一样先把四个基础层逐一搭好：程序结构、大语言模型、对话上下文和外部工具。  
这四层分别回答四个问题：  
程序如何围绕目标运行？  
模型怎样进入 Python 程序？  
上一轮对话如何影响下一轮回答？  
程序怎样获得模型文本之外的真实执行能力？

第一章从一个规则温控程序出发，观察目标、环境、观察、决策和行动怎样形成闭环。这个例子不依赖大语言模型，它首先帮助我们看清 Agent 的结构，而不是把 Agent 简单理解为某种模型或框架。

第二章开始构建城市旅行助手。程序第一次把用户消息发送给真实模型，并取得一条自然语言回答。第三章在此基础上保存有序的 `messages`，使模型能够理解“它”“继续解释”和“刚才提到的景点”等依赖历史的表达。第四章再加入天气查询、景点信息和计算器，使程序能够读取明确数据并完成确定性计算。

四章之间的关系可以概括为：

```text
程序运行结构
→ LLM 生成
→ messages 提供上下文
→ Tool 完成真实执行
```

阅读这一部分时，需要始终区分两件事：模型生成了一段文字，与程序真正执行了一项操作。模型可以描述天气，也可以建议进行计算，但只有明确的工具函数被程序调用后，外部数据读取和确定性计算才真正发生。

第一部分结束时，城市旅行助手已经能够调用模型、保存对话并执行工具。不过，模型与工具之间仍然没有直接连接：模型还不能按照程序约定提出一项可执行请求，工具名称和参数仍由开发者手动指定。
